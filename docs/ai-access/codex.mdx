# Connect Codex / ChatGPT

DocJacket works with every OpenAI surface that speaks MCP:

- **Codex CLI** — the open-source command-line tool for developers
- **Codex for Work** — OpenAI's hosted Codex for teams
- **ChatGPT** — with MCP connectors enabled in your account settings

The same DocJacket MCP server backs all three. Connect once per surface.

## Before you start

- **A DocJacket account on any plan.** On DocJacket's Free plan, your organization gets 50 AI tool calls a month; paid plans have no monthly limit. See [Free plan limit](/docs/ai-access/use-from-your-assistant#free-plan-limit).
- **For ChatGPT:** your ChatGPT plan must allow custom connectors. Not every plan does, and on a business workspace an admin may need to turn it on first.
- **On some plans, ChatGPT only allows read-only connectors.** If DocJacket can read your deals from ChatGPT but can't make changes, check your ChatGPT plan.

## Quick start (Codex)

Install the DocJacket plugin for Codex:

```bash
codex plugin marketplace add docjacket-inc/codex-plugin
codex plugin install docjacket
```

On the first DocJacket tool call, your browser opens the DocJacket sign-in and consent screen. Choose the access you want and click **Allow**. Codex keeps the sign-in in your computer's keychain. You don't paste a token.

The plugin is on GitHub at [docjacket-inc/codex-plugin](https://github.com/docjacket-inc/codex-plugin).

## Quick start (ChatGPT)

1. In ChatGPT on the web, add a custom connector. ChatGPT also calls this a custom MCP server. Where this sits in ChatGPT's settings depends on your plan.
2. Type a name, such as DocJacket, paste `https://mcp.docjacket.com/mcp`, and choose OAuth for sign-in.
3. Sign in to DocJacket, choose the access you want, and click **Allow**.
4. Start a new chat. DocJacket's tools are now available for the access you chose.

## Try it

Ask Codex or ChatGPT:

> "Use DocJacket to summarize what needs my attention today."

The assistant will call `get_next_required_actions` and come back with a ranked list of transactions, overdue-first, with rationales explaining why each one matters.

Other good prompts:

- "Use DocJacket to search for any deals at 123 Main."
- "Use DocJacket to list deadlines this week."
- "Use DocJacket to show open tasks on the [property] deal."
- "Use DocJacket to look up the listing agent on [property]."
- "Use DocJacket to check what documents are missing for [property]."

The "Use DocJacket to…" prefix is the convention OpenAI's surfaces follow when invoking a specific MCP connector. You can drop it once the assistant gets used to your patterns.

## What Codex and ChatGPT can do

DocJacket's tools come in three permission tiers. You pick one when you consent, and DocJacket enforces it. A read-only connection cannot call a write tool even if the assistant tries.

| Tier | What it allows | For example |
|---|---|---|
| `read` | Look things up. Changes nothing. | `search_transactions`, `get_upcoming_key_dates`, `get_next_required_actions` |
| `draft` | Change tasks, key dates, Playbooks and status inside DocJacket. Sends no email. | `create_tasks`, `update_key_date`, `apply_checklist` |
| `actions` | Send emails you approve, and make other changes | `send_client_update`, `apply_extraction`, `create_reminder` |

An email sent from the `actions` tier goes out only from your own connected Gmail or Outlook account, never from DocJacket's email service. Connect one in DocJacket under **Settings > Integrations** first. See [Emails send from your own mailbox](/docs/ai-access/use-from-your-assistant#own-mailbox).

**[Browse every tool →](/docs/ai-access/tool-catalog)**: the complete catalog with descriptions, gotchas, and example calls.

You don't need to remember tool names; Codex and ChatGPT pick the right tool from your question. To see the inventory *your* connection can reach, ask:

> "Use DocJacket's `mcp_catalog` to list the tools by category."

## Skills shipped with the plugin

The Codex plugin (version 0.9.0) ships fourteen workflow skills the assistant picks from automatically:

`daily-triage` · `email-triage` · `contract-intake` · `document-filing` · `closing-prep` · `follow-up-drafting` · `deal-updates` · `contact-management` · `playbook-builder` · `workspace-setup` · `compliance-filing` · `execution-workflow` · `tc-context` · `dj-cli`

What each one does: [Connect Cowork](/docs/ai-access/cowork#skills) (the Claude and Codex plugins share the same skills).

Each is a recipe the assistant follows when you ask the corresponding question. Example invocations:

In Codex CLI:

```
$docjacket-daily-triage
```

In ChatGPT, just ask in plain English:

> "Use DocJacket to do a daily triage of my pipeline."
> "Use DocJacket to find the listing agent on 1234 Main and summarize the deal context."
> "Use DocJacket to review extraction results for this PDF." Action tools are required to create the transaction from chat.

Either way you get a ranked, structured response — the skill carries the formatting and the recipe.

## Permissions, audit, and revocation

Same as the Claude side. Each Codex or ChatGPT install gets its own `client_id`.

Inside DocJacket:

- **Settings → API & AI Access** lists every connected client with last-used timestamp.
- **Activity log** shows every tool call: who, what, when, what arguments, what result.
- **Revoke** any client with one click. The next request returns HTTP 401 — the assistant will fall back to re-consent if you want to reconnect.

## Not seeing a new tool?

DocJacket adds new tools from time to time. ChatGPT keeps the list of DocJacket tools from the day you connected, so it may not show the new ones. To get them:

1. In ChatGPT, open **Settings**, then **Plugins**, then **DocJacket**.
2. Scroll to **Manage app**.
3. Press **Refresh tools**.
4. Start a new chat.

## Troubleshooting

**"Authorization with the MCP server failed"** — Remove the connector from Codex / ChatGPT settings and re-add it to clear stale state. If the problem persists, send the reference ID the assistant shows to <a href="mailto:support@docjacket.com">support@docjacket.com</a>.

**Codex CLI auth keeps re-prompting** — Running several Codex processes against one saved credential no longer causes this; simultaneous refreshes are handled ([how rotation works](/docs/ai-access/oauth#refresh--rotation)). If you are still being asked to reconnect, the saved credential is stale or was revoked — delete the entry from `~/.codex/credentials` and re-consent.

**"Token is invalid, expired, or revoked"** — Either you revoked the client in DocJacket → Settings → API & AI Access, or the refresh token expired after 90 days of inactivity. Re-consent to reconnect.
